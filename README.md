# Serenity Desktop Environment (SDE)

A project to recreate the **SerenityOS desktop experience** on **Wayland** and **Linux**.

SerenityOS describes itself as "a love letter to '90s user interfaces". SDE is a love letter to SerenityOS.

![The SDE desktop: the SerenityOS Taskbar with its system menu open to Development -> Profiler, a Terminal running `uname -a` / `df -Th`, the active File Manager, the Browser on serenityos.org, and the System Monitor's Performance tab, on the SerenityOS grid wallpaper. The screenshot is generated by `scripts/run-desktop-scene.sh --headless --screenshot docs/images/sde-desktop.png`.](docs/images/sde-desktop.png)

The rough-goal of SerenityOS is "a marriage between the aesthetic of late-1990s productivity software and the power-user accessibility of late-2000s *nix".
SerenityOS does an excellent job of capturing that aesthetic. We believe "the power-user accessibility of late-2000s *nix" is best expressed by modern Linux with its broad hardware compatibility, vast software catalog, and container ecosystem.
The goal of SDE is to faithfully recreate the SerenityOS UX on Linux.

The SDE desktop consumes only 150 MB of RAM with Taskbar and applets running.

## Repositories

The stack is split across a small family of repositories:

| Repository | Role |
|---|---|
| [`SerenityOS/serenity`](https://github.com/SerenityOS/serenity) | Upstream source of LibGUI / LibGfx / applications / themes / fonts. Consumed **unmodified** wherever possible. |
| [`jmalcolm137/libgui-wayland`](https://github.com/jmalcolm137/libgui-wayland) | **LibWindowServer**: runs unmodified Serenity `LibGUI`/`LibGfx` apps natively on Wayland by implementing the WindowServer protocol in-process. |
| **this repo** | The **system side**: `WindowServer` (a [reasonably complete](docs/23-wayland-protocols.md) wlroots-based Wayland compositor) and the session that runs the **unmodified SerenityOS shell apps** (Taskbar, applets, Desktop, Settings) as Wayland clients, plus services/settings and the integration that turns LibWindowServer-powered apps into a coherent desktop session. |

## Running

### Arch Linux packages

Download both packages and `SHA256SUMS` from the
[v0.1.0 release](https://github.com/jmalcolm137/serenity-desktop-environment/releases/tag/v0.1.0).
Install the framework first, then the session package:

```sh
sudo pacman -Syu
sha256sum -c SHA256SUMS
sudo pacman -U serenity-lagom-git-0.1.0-1-x86_64.pkg.tar.zst
sudo pacman -U serenity-desktop-environment-git-0.1.0-1-x86_64.pkg.tar.zst
```

Install a display manager such as SDDM if you do not already have one:

```sh
sudo pacman -S --needed sddm
sudo systemctl enable --now sddm
```

Log out, choose **Serenity Desktop Environment** at the login screen, and log
back in. The session package includes XWayland support.

### Build from source

```sh
scripts/build-full-sde.sh --with-apps
```

### Real hardware (DRM/KMS + libinput)

From a TTY (`Ctrl+Alt+F3`) or a display manager session entry:

```sh
scripts/start-sde-session.sh
```

### Display manager (SDDM, GDM, ...)

Install the session entry so the login screen lists **Serenity Desktop
Environment**:

```sh
sudo scripts/install-session.sh    # /usr/local/bin/sde-session + /usr/share/wayland-sessions/sde.desktop
# ... then log out and pick it at the login screen.
# Remove it with: sudo scripts/install-session.sh --uninstall
```

## Reporting problems

Use [GitHub Issues](https://github.com/jmalcolm137/serenity-desktop-environment/issues)
and include:

- the output of `pacman -Q serenity-desktop-environment-git serenity-lagom-git`
- your GPU and whether you are using DRM/KMS or the headless backend
- the relevant part of `~/.local/state/sde/session.log`
- whether the problem also happens with `SDE_SAFE_MODE=1`

## Relationship

SDE is not affiliated with, endorsed by, or sponsored by the SerenityOS project.
The primary goal of SDE is to run the real, unmodified SerenityOS userland on Linux.
If you want to see changes in SDE, we suggest you contribute them to SerenityOS first.
Changes that are Linux specific may not be accepted into SerenityOS and may be accepted here.
