# R4.4 — Compositor Configuration & Live Reload

**Status:** Draft v0.1 · **Date:** 2026-10-11
**Related:** [`11-r4-implementation-plan.md`](11-r4-implementation-plan.md) §R4.4 · [`04-known-gaps.md`](04-known-gaps.md) · [`08-compositor-gaps.md`](08-compositor-gaps.md)

This is the **configuration seam** for R4.4–R4.8: a documented, validated
`WindowServer.ini` that the compositor live-reloads, with a `scripts/sde-config`
helper. The settings backends (R4.5 display, R4.6 input, R4.7 appearance, R4.8
workspaces) write through this file rather than inventing per-feature mechanisms.

> **Status.** The schema, validation, live reload, `sde-config`, the
> `[Tiling]`/`[Focus]`/`[Effects]`/`[Output]` consumers, and configurable
> **`[Keybindings]`** have landed and are covered by `scripts/run-config-test.sh`.
> **Not yet done:** the `org.freedesktop.portal.Settings` backend (below).

---

## 1. Where the config lives

The shared SDE state directory `$XDG_CONFIG_HOME/sde` (`SDE_STATE_DIR` overrides),
the same place as the wallpaper/theme state:

```
$XDG_CONFIG_HOME/sde/WindowServer.ini
```

The compositor is **Linux-native aware** and layered: the effective value for a
key is the user's file first, then the SerenityOS defaults under
`$SERENITY_RES_ROOT/../etc/WindowServer.ini`. A missing key means "use the
built-in default".

The **session** layer has its own policy file in the same directory —
`$XDG_CONFIG_HOME/sde/session.conf` (KEY=value; idle/lock, restart budget,
watchdog, safe mode, autostart), read by `scripts/sde-session.sh` with the same
*environment > file > default* precedence. See
[`12-r4.3-portable-session-integration.md`](12-r4.3-portable-session-integration.md) §4.

## 2. Schema

All keys are optional.

| Section | Key | Type | Range / values | Default | Consumed by |
|---|---|---|---|---|---|
| `[Workspaces]` | `Rows` | int | 1–16 | 2 | the window-stack grid (WS1) |
| `[Workspaces]` | `Columns` | int | 1–16 | 2 | the window-stack grid (WS1) |
| `[Applet]` | `Order` | list | comma-separated names | SerenityOS order + `WiFi` + `Battery` | the applet area (WS4). Applets are laid out **right-to-left by descending index, so the *last* entry is rightmost**; SDE appends `WiFi` then `Battery` (its own applets) to the end, so Wi-Fi sits just left of the battery applet at the far right by default. |
| `[Tiling]` | `EdgeThreshold` | int | 1–512 (px) | 48 | drag-to-edge arming distance (WS2) |
| `[Tiling]` | `DragToEdge` | bool | true / false | true | enable drag-to-edge snapping (WS2) |
| `[Focus]` | `FollowsMouse` | bool | true / false | false | focus the window under the cursor |
| `[Effects]` | `WindowGeometry` | bool | true / false | true | the geometry HUD while moving/resizing (WS2) |
| `[Effects]` | `AnimateWindows` | bool | true / false | true | minimize/restore outline animation between the window and its Taskbar button (SerenityOS `Window::start_minimize_animation`) |
| `[Output]` | `DefaultScale` | number | 0 (auto), or 0.5–4.0 | 0 | output scale (HiDPI; fractional allowed, e.g. `1.5`), applied live; `SDE_OUTPUT_SCALE` overrides it |
| `[Output]` | `Renderer` | name | `auto` / `gles2` / `vulkan` / `pixman` | `auto` | the wlroots renderer (R6/N5); `pixman` is the software fallback, and `SDE_RENDERER` overrides it |
| `[Log]` | `Level` | name | `error` / `warn` / `info` / `debug` | `error` | compositor verbosity (R6/N8); `SDE_LOG_LEVEL` overrides it |
| `[Placement]` | `Windows` | list | `title:X,Y,W,H;...` | (empty) | initial window geometry rules; the first rule whose title is a substring of a new window's title wins (e.g. for `scripts/run-desktop-scene.sh`) |

Booleans accept `true/false`, `1/0`, `yes/no`, `on/off` (case-insensitive).

`[Output] DefaultScale` is the config home for the output scale (0 = auto, else
0.5–4.0; fractional allowed, e.g. `1.5`), applied **live**; the `SDE_OUTPUT_SCALE`
environment variable still overrides it so tests can force a scale without a config
file. The client backing store rasters at the output scale (host M8 resolved) and
`wp-fractional-scale-v1` is served; see
[`13-native-session-and-aur-packaging.md`](13-native-session-and-aur-packaging.md)
Appendix A.

### `[Keybindings]`

Each key maps a named **action** to one or more combos
(`Modifier+…+Keysym`, comma-separated for several). Modifiers are `Ctrl`, `Alt`,
`Shift`, `Super` (aliases `Logo`/`Meta`); keysyms are XKB names (`Left`, `Tab`,
`L`, `Page_Down`, …).

| Action | Default combos |
|---|---|
| `SwitchWorkspaceLeft/Right/Up/Down` | `Ctrl+Alt+←/→/↑/↓` |
| `CarryWorkspaceLeft/Right/Up/Down` | `Ctrl+Shift+Alt+←/→/↑/↓` |
| `TileLeft` / `TileRight` | `Super+←` / `Super+→` |
| `Maximize` / `Minimize` | `Super+↑` / `Super+↓` |
| `MaximizeHorizontal` | `Super+Alt+←`, `Super+Alt+→` |
| `MaximizeVertical` | `Super+Alt+↑`, `Super+Alt+↓` |
| `Lock` | `Super+L` |

The compositor resolves a pressed key to an action via the table and runs it
(`WindowManager::perform_action`). The defaults reproduce the previous hardcoded
bindings, so nothing changes until a combo is edited.

## 3. Validation and diagnostics

An invalid value is **rejected** — the previous value is kept (so a bad edit does
not clobber a running session) — and recorded as a diagnostic; the compositor
logs each one and `sde-config validate` fails with a clear message:

```
$ sde-config set Workspaces Rows 99
$ sde-config validate
sde-config: [Workspaces] Rows='99' invalid (expected 1-16)
$ echo $?
1
```

The same rules run in the compositor (`WindowServer --check-config`), so there is
a single source of truth.

## 4. Live reload

The compositor watches the state directory and the file; a single edit produces a
burst of inotify events, coalesced into **one** reload (`Config::watch`). On
reload it re-applies the values: the workspace grid, tiling threshold, drag-to-edge,
follows-mouse, geometry HUD, and output scale (a live `[Output] DefaultScale` edit
re-scales the outputs), plus the on-disk screen layout (`screenlayout.ini`, §6).

Persisting the layout is itself defensive: `persist_screen_layout` skips the write
when the live layout already matches `screenlayout.ini` (matched by device), and
otherwise writes **coalesced** (~120 ms). Without both, creating several outputs at
startup would write a partial layout after each output — clobbering the saved
entries for outputs not yet present, after which the file watcher reloads the
truncated file and the remaining outputs fall back to auto-placement.

## 5. `scripts/sde-config`

```
sde-config path                          # the user config file path
sde-config list                          # the effective configuration
sde-config get <section> <key>           # an effective value
sde-config set <section> <key> <value>   # set a value in the user config
sde-config validate                      # validate (non-zero exit on error)
```

`get`/`list`/`validate` reuse the compositor's own parser (via
`WindowServer --print-config` / `--check-config`), so they always agree with what
the compositor will do.

## 6. Settings portal

**Interop (P8).** The appearance subset is exposed through an
**`org.freedesktop.portal.Settings`** backend: `tools/sde-settings-portal.c`
implements **`org.freedesktop.impl.portal.Settings`** and answers `color-scheme`,
`accent-color` and `contrast` from the active SDE theme (the theme broker
`$XDG_RUNTIME_DIR/sde-theme`), emitting `SettingChanged` on a theme change. It is
a host D-Bus service (GIO/GDBus) started with the session
(`start-sde-session.sh` / `start-sde-nested.sh`); it is harmless when
`xdg-desktop-portal` is absent (R4.3 keeps portals optional).

> R5: the session now prefers the combined backend
> `build/tools/xdg-desktop-portal-serenity` (it also implements this Settings
> interface) and only falls back to `sde-settings-portal` when it is not built.

- `color-scheme`: 2 (prefer-light) or 1 (prefer-dark), from the theme's `Window`
  colour luminance.
- `accent-color`: the theme's `Accent` colour (fallback `Selection`).
- `contrast`: 0 (no preference).

Route `org.freedesktop.portal.Settings` to it in
`$XDG_CONFIG_HOME/xdg-desktop-portal/portals.conf`:

```ini
[preferred]
org.freedesktop.portal.Settings=sde
```

Then

```
gdbus call --session --dest org.freedesktop.portal.Desktop \
  --object-path /org/freedesktop/portal/desktop \
  --method org.freedesktop.portal.Settings.ReadAll org.freedesktop.appearance
```

returns the SDE scheme. (The Serenity shell keeps the `serenity-window`/
theme-broker path.) Verified by `scripts/run-settings-portal-test.sh`.

## 7. Exit test

`scripts/run-config-test.sh`:

- **defaults** come from the schema;
- **set/get** round-trips through `sde-config`;
- **validation** rejects an out-of-range value with a clear error;
- **live reload** changes a running compositor (setting `[Workspaces] Rows=4`
  re-grids the session without a restart).

## 8. Output layout (R4.5)

Output/display settings use a second state file, **`screenlayout.ini`** in the
same state directory, in the Serenity WindowServer `ScreenLayout` format:

```ini
[Screens]
MainScreen=0
[Screen0]
Mode=Device
Device=HEADLESS-1
Left=0
Top=0
Width=1280
Height=720
ScaleFactor=1
```

- The **compositor** writes it whenever outputs appear or a
  `zwlr_output_management_v1` configuration is applied (the live layout), and
  reads it when an output is created to apply a saved resolution/scale/position.
  Edits to the file are watched and re-applied live.
- The **port** (`WindowServerConnection::get_screen_layout` /
  `set_screen_layout`) reads/writes the same file, so DisplaySettings ▸ **Monitor**
  shows the real output and drives the compositor.

Verified by `scripts/run-output-test.sh` (persisted layout, saved layout applied
on creation, live re-apply). Fractional scaling is deferred to R6.

## 9. Input settings (R4.6)

Input/pointer/keyboard settings use a third state file, **`input.ini`**, in the
same state directory:

```ini
[Mouse]
Acceleration=1.0
ScrollStepSize=1
DoubleClickSpeed=250
ButtonsSwitched=false
NaturalScroll=false
AccelProfile=adaptive
TapToClick=false
LeftHanded=false
DisableWhileTyping=true
[Keyboard]
Layouts=us
Variant=
Model=pc105
Options=
RepeatDelay=600
RepeatRate=25
```

The **compositor** applies these to libinput devices (acceleration profile/speed,
tap-to-click, natural scroll, left-handed, disable-while-typing), to the event
path (natural scroll, scroll step, buttons-switched, double-click speed), and
builds the xkb keymap from the keyboard layouts; edits are watched and re-applied.

The **ranges** (accel min/max, scroll-step min, double-click min/max) live in the
main schema, `WindowServer.ini [Input]`, and the port serves them to clients via
`get_mouse_acceleration_min`/`_max`, `get_scroll_step_size_min`,
`get_double_click_speed_min`/`_max`, so the settings UI does not hardcode them.
MouseSettings' cursor theme/highlight tabs are backed by `cursor.ini` (applied to
the real cursor in R4.7).

Verified by `scripts/run-input-settings-test.sh` (applied at startup, live
re-apply, xkb layout, ranges from the schema). MouseSettings is wired through the
WindowServer protocol (the settings methods read/write `input.ini`, and the
ranges come from `WindowServer.ini [Input]`); KeyboardSettings reads the current
and available xkb layouts from the port and writes changes back to `input.ini`.

## 10. Theme (R4.9)

The chosen system theme is persisted in `WindowServer.ini`:

```ini
[Theme]
Name=Dark
Path=/path/to/res/themes/Dark.ini
```

The live channel is the theme broker (`$XDG_RUNTIME_DIR/sde-theme`, written by the
port when DisplaySettings ▸ **Themes** applies a theme); the compositor watches it,
applies the theme, and persists `[Theme]`. At startup the compositor applies
`[Theme]`, and clients pick it up (the broker, or `[Theme]` when there is no live
value). Verified by `scripts/run-themes-test.sh`.
