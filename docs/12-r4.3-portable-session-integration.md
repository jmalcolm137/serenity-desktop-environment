# R4.3 — Portable Session Integration (logind/systemd optional)

**Status:** Implemented (session layer) · v0.2 · **Date:** 2026-10-10
**Related:** [`01-objectives.md`](01-objectives.md) §6 (P4, P8, P9), §11 · [`11-r4-implementation-plan.md`](11-r4-implementation-plan.md) §3 (R4.3), §4, §7 · [`07-systemserver-roles.md`](07-systemserver-roles.md) · [`06-service-layering.md`](06-service-layering.md)

This document is the design and execution plan for **R4.3**, reframed. It
supersedes the R4.3 description in
[`11-r4-implementation-plan.md`](11-r4-implementation-plan.md) §3 while keeping
that document's milestone table intact (R4.3 keeps its number and position on the
critical path). It is written to be picked up on its own.

---

## 1. Why we are changing R4.3

[`11-r4-implementation-plan.md`](11-r4-implementation-plan.md) §3 defines R4.3 as
*"logind / systemd / portal session integration"* and its exit test as scripted
env assertions plus a Settings-portal query. As written, it reads as a
**dependency on systemd-logind** and on the systemd user manager
(`graphical-session.target`, `dbus-update-activation-environment` importing into
the systemd user environment).

That contradicts the project's portability principle **P4** ("portable protocols
first; per-compositor backends behind interfaces") and the non-goal of replacing
the Linux init/login stack
([`01-objectives.md`](01-objectives.md) §5). SDE should run on a machine with no
systemd at all — a bare TTY with `seatd`, a container, or nested on a host
desktop — and should *opportunistically* use logind/systemd when they are
present, never require them.

**Reframe.** Treat systemd/logind as **optional accelerators that are detected at
runtime**. R4.3 becomes a small, portable **session-integration layer** with
provider interfaces and portable fallbacks. This is the same shape the project
already uses elsewhere: *"prefer the session service, else in-process fallback"*
([`06-service-layering.md`](06-service-layering.md)).

---

## 2. Principle

1. **No hard init/login dependency.** The session must start, run, lock, and
   (where the OS permits) power off **without logind or systemd**.
2. **Detect, don't assume.** Every integration (logind, systemd user manager,
   D-Bus session bus, `xdg-desktop-portal`, seatd) is probed; if present it is
   used, if absent the session degrades gracefully with a clear, actionable
   message.
3. **The compositor stays pure.** logind/systemd awareness lives in the **session
   layer**, not in `WindowServer`. The compositor's only seat dependency is the
   **libseat** *library*, which is itself backend-agnostic (P1/P4).
4. **Ordered provider chains.** Each capability is served by an ordered list of
   providers; the first that can act wins. Each provider is independently
   testable via an `SDE_*_CMD` seam (the pattern already used by
   `scripts/sde-power.sh`).
5. **Everything we ship is portable (P8/P9).** Our env setup, power router, idle
   daemon and lock path must work under **other** compositors and init systems,
   using standard mechanisms (D-Bus, Wayland protocols), not SDE-private or
   init-system-private interfaces.

## 3. What R4.3 actually does: four jobs

### 3.1 Session environment (easy)

Always set the standard environment in the supervisor (`scripts/sde-session.sh`
already sets some of this):

| Variable | Value |
|---|---|
| `XDG_SESSION_TYPE` | `wayland` |
| `XDG_SESSION_CLASS` | `user` (or `greeter` for a future greeter) |
| `WAYLAND_DISPLAY` | the session socket (`sde`) |
| `XDG_CURRENT_DESKTOP` | `SDE` |
| `XDG_SESSION_DESKTOP` | `SDE` |
| `DESKTOP_SESSION` | `sde` |
| `XDG_RUNTIME_DIR` | inherited; already required by the supervisor |

Then, **best-effort only**, push these onto the **D-Bus activation environment**
(`dbus-update-activation-environment`, or a direct D-Bus `UpdateActivationEnvironment`
call) **if** a session bus and the helper exist. This does **not** require
systemd: the goal is only that D-Bus-activated services (portals) see a Wayland
session. If it is unavailable, continue silently.

**Do not** order under `graphical-session.target`; the supervisor
(`scripts/sde-session.sh`) owns session ordering. A systemd unit may be offered
later as an *optional wrapper*, never as the mechanism.

### 3.2 Seat / DRM master / VT switch (the only genuinely hard part)

We already do not depend on logind here: `wlr_backend_autocreate` uses
**libseat**, which selects one of three interchangeable backends:

| libseat backend | When to use | Notes |
|---|---|---|
| `logind` | systemd-logind present | Zero-config where available; opportunistic, not required |
| `seatd` | **recommended portable default** | `seatd` daemon + socket; no systemd |
| `builtin` | no seat daemon, direct TTY | needs device permissions (`video`/`render` groups or root); manages DRM/input directly |

Rules:

- **Do not reimplement DRM master or VT switching.** Let libseat abstract it.
  Keep `LIBSEAT_BACKEND` and `SEATD_SOCK` as the configuration seam.
- **Be seat-aware (multi-seat).** `scripts/sde-seat.sh` derives/export
  `XDG_SEAT` (default `seat0`) and `XDG_VTNR` (logind, else the active VT) so
  apps and portals know their seat. The runtime namespaces are **per seat**:
  the Wayland socket (`SDE_SESSION_DISPLAY`, `sde` → `sde-<seat>`), the
  supervisor pid file, the `/bin` shadow dir, and the WindowManagerServer socket
  (`SDE_WM_PORTAL_PATH`, `/tmp/portal/wm` → `/tmp/portal/wm-<seat>`). `seat0`
  keeps the bare names. The port's clients honour `SDE_WM_PORTAL_PATH`
  (libgui-wayland patch `0041`), and the compositor honours it when it listens.
- Provide a **capability probe** (see §4) that reports the active backend, and a
  clear startup error with guidance when none is usable
  (`start-sde-session.sh` preflights the DRM device; the compositor explains a
  failed backend).
- **Nested** (`scripts/start-sde-nested.sh`) needs no seat at all — keep it the
  primary development path, so R4.3 work is testable without hardware.
- A display manager / greeter stays out of scope (we use SDDM/GDM): we ship a
  **session entry** (`session/sde.desktop.in` + a launcher + `scripts/install-session.sh`,
  installed to `/usr/share/wayland-sessions`) that any login manager can list and
  launch, and require none. See
  [`13-native-session-and-aur-packaging.md`](13-native-session-and-aur-packaging.md) §6.

### 3.3 Power / logout / suspend (medium)

Turn `scripts/sde-power.sh` from a logind-first script into an **ordered provider
chain**; the first provider that can service the action wins:

| Order | Provider | Actions | Requirement |
|---|---|---|---|
| 1 | `SDE_POWER_CMD` override | any | test/embed seam (already present) |
| 2 | **logind** (D-Bus `org.freedesktop.login1`; `loginctl`, else `busctl`) | shutdown, reboot, suspend, logout | logind present |
| 3 | **Portable fallbacks** | logout → supervisor exits; suspend → `rtcwake` / `pm-suspend` if present; shutdown/reboot → direct `reboot(2)`/`RB_POWER_OFF` (or a small privileged helper) *if* permissions allow | privileges |
| 4 | **Unavailable** | — | returns a clear "unavailable" status |

- Keep the `/bin` shadow helpers (`shutdown`/`reboot`/`logout`/`suspend`) already
  landed in `scripts/sde-session.sh` + the port's `resolve_executable_path()`
  (`patches/0011`): they make the **unmodified Taskbar `ShutdownDialog`**
  provider-agnostic.
- Each action exposes an **availability** result so settings/UI can grey out what
  cannot work in the current environment.
- **Suspend/resume hooks (R6).** `scripts/sde-sleep.sh` listens for logind's
  `PrepareForSleep` (via `gdbus`/`dbus-monitor`): it locks the session on suspend
  (unless `lock_on_suspend=0`) and on resume unblanks (`sde-dpms on`) and runs the
  optional `suspend_hook`/`resume_hook`. It is a no-op without logind/D-Bus; the
  compositor relies on libseat to release and re-acquire DRM master across the
  sleep.

### 3.4 Portals & D-Bus (optional)

`xdg-desktop-portal` is a D-Bus service, not a systemd service: where a session
bus exists it activates over D-Bus, with or without systemd. Rule:

- **Start/require nothing.** If `xdg-desktop-portal` (and a backend) is present,
  provide a `portals.conf` and let D-Bus activation run it.
- If it is absent, the session and the Serenity shell must be fully functional via
  the in-process Serenity shims.
- R4.4's **Settings portal** (appearance) is therefore *"exposed if a bus + portal
  exist, else the theme broker keeps working"* — not a hard dependency.

## 4. Structure: providers, probing, seams

- **Capability probe.** A new `scripts/sde-capabilities` reports what the session
  can do, in both human and machine-readable (`key=value` or `--json`) form, for
  the supervisor and the settings layer. Illustrative output:

  ```
  seat=seatd            # logind | seatd | builtin | none
  seatd_sock=/run/seatd.sock
  logind=absent
  dbus_session_bus=present
  portal=xdg-desktop-portal-absent
  power.shutdown=unavailable
  power.reboot=unavailable
  power.logout=available
  power.suspend=unavailable
  ```

- **Layering.** Policy lives in the **session layer**:
  - `scripts/sde-session.sh` — env + ordering + provider selection,
  - `scripts/sde-seat.sh` — seat identity (`XDG_SEAT`/`XDG_VTNR`) + per-seat names,
  - `scripts/sde-power.sh` — the power provider chain,
  - `scripts/sde-capabilities` — the probe used by both.
  The compositor is unchanged except for consuming libseat (already the case).

- **Seams.** Follow the existing `SDE_*_CMD` pattern so every provider is
  independently testable and embeddable: `SDE_POWER_CMD`, plus (as needed)
  `SDE_SEAT_BACKEND`, `SDE_DBUS_ENV_CMD`, `SDE_PORTAL_DIR`.

- **Session policy file (R6).** User-facing session policy lives in
  `$XDG_CONFIG_HOME/sde/session.conf` — the session sibling of `WindowServer.ini`
  (same state directory; `SDE_STATE_DIR` overrides it, and `SDE_SESSION_CONF`
  overrides the path). One `KEY=value` per line, `#` comments; precedence is
  **environment > file > built-in default**, so tests and embedding can force a
  value without editing the file. Keys: `idle_seconds`, `idle_dpms_seconds`,
  `lock_command`, `max_restarts`, `restart_delay`, `watchdog_seconds`,
  `safe_mode`, `autostart`, `autostart_dir`. Structural/launch seams
  (`SDE_SESSION_COMPOSITOR`, `*_BIN_DIR`, `SDE_DBUS_ENV_CMD`) stay environment-only.

## 5. Exit tests

**Headless (no logind/systemd, CI):**

- `scripts/run-session-env-test.sh` — with logind/systemd/D-Bus absent (mocked),
  the supervisor still starts, sets the correct environment, and does **not** fail
  if the D-Bus activation helper is missing.
- `scripts/run-power-providers-test.sh` — drives `sde-power.sh` through each
  provider in the chain with mocks and asserts: override wins; logind used when
  present; fallback used when not; `unavailable` reported cleanly; the `/bin`
  shadow helpers route to the selected provider (`run-binpath-test.sh` already
  covers the shadow).
- `scripts/run-capabilities-test.sh` — the probe reports the expected
  `key=value` set for a simulated environment (no bus / no logind / no portal).
- Extend `scripts/run-session-test.sh` with a "degraded environment" phase.

**Manual (real hardware):**

- Start the session from a TTY with **seatd** and with **builtin** (no logind) —
  DRM master, input and VT switch work via libseat.
- Start nested (`start-sde-nested.sh`) — no seat needed.
- If logind is present, confirm it is used opportunistically for power.

## 6. Decisions to record

| # | Decision | Options | Leaning |
|---|---|---|---|
| D1 | Seat provider default order | `logind → seatd → builtin` vs `seatd → logind → builtin` | Probe `logind → seatd → builtin` (opportunistic logind, zero-config where present) unless predictability is preferred; record in the doc |
| D2 | Privileged power fallback | ship a helper vs "power unavailable without logind/polkit" | Start with "unavailable + clear message"; add a helper only if a no-logind reboot is required |
| D3 | Suspend fallback binaries | `rtcwake`, `pm-suspend`, none | Best-effort; `unavailable` otherwise |
| D4 | Push env to D-Bus activation | always-attempt-if-present vs opt-in | Attempt if present; never fail |
| D5 | Optional systemd unit wrapper | provide later vs never | Optional wrapper allowed; never the mechanism |

## 8. Out of scope (unchanged from R4)

- An SDE greeter and PAM login (future; R4.3 ships the launchable **session
  entry** — `scripts/install-session.sh` + `session/` — for SDDM/GDM).
- `xdg-desktop-portal` *backend implementation* — R4.4 (Settings) and R5
  (capture/input/shortcuts) own that; R4.3 only makes portals optional-but-wired.
- `ext-transient-seat-v1` and multi-seat — R4.3/R4.6/R6.
- Non-Linux targets. "Portable" here means **init-system- and
  login-stack-agnostic on Linux**, not cross-kernel.

## 9. Implementation status (landed)

- **Env** (`sde-session.sh`): `XDG_SESSION_TYPE`/`CLASS`, `XDG_CURRENT_DESKTOP`/
  `XDG_SESSION_DESKTOP`, `DESKTOP_SESSION`, `WAYLAND_DISPLAY` are set (SDE identity
  forced, even nested); the D-Bus activation environment is pushed best-effort via
  `SDE_DBUS_ENV_CMD` / `dbus-update-activation-environment`, never required.
- **Power** (`sde-power.sh`): ordered provider chain (`SDE_POWER_CMD` → logind →
  portable fallbacks → *unavailable*) with `--check`/`--list`; the logout fallback
  stops the supervisor (pid file). `/bin` shadow helpers route the unmodified
  Taskbar menu here (`run-binpath-test.sh`).
- **Capabilities** (`sde-capabilities`): probes seat (`logind`/`seatd`/`builtin`),
  logind, D-Bus session bus, portal, and `power.*`; `key=value` or `--json`.
- **Seat:** unchanged — `libseat` via `wlr_backend_autocreate` (P1/P4); nested
  needs none. **Multi-seat / VT-switch polish:** `scripts/sde-seat.sh` derives
  `XDG_SEAT`/`XDG_VTNR` and the session namespaces its runtime per seat (Wayland
  socket, supervisor pid file, `/bin` shadow dir, `SDE_WM_PORTAL_PATH`);
  `start-sde-session.sh` preflights the DRM device. Covered by
  `scripts/run-multiseat-test.sh`. Manual hardware checks pending; suspend/resume
  hooks are still open.
- **Tests:** `run-session-env-test.sh`, `run-power-providers-test.sh`,
  `run-capabilities-test.sh`, and a degraded phase in `run-session-test.sh`.
- **Hardening (R6/N4):** the supervisor watches a liveness heartbeat the
  compositor writes (`SDE_HEARTBEAT_FILE`) and restarts a *wedged* compositor
  (event loop blocked), not just a crashed one. After the restart budget it drops
  to **safe mode** — a minimal shell (`SDE_SESSION_COMPOSITOR_SAFE`), no
  autostart — instead of ending the session, and only gives up if safe mode also
  keeps failing. Covered by `run-session-test.sh` phases (H)–(K) and the heartbeat
  assertion in `run-headless-test.sh`.
